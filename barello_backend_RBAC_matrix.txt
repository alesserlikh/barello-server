28. Ключевые правила
──────────────────────────────────────────────────
User
  — должен иметь минимум один из контактов: phone или email

Supplier
  — отдельный логин компании без модели сотрудников
  — passwordHash NOT NULL — нельзя создать аккаунт поставщика без пароля

Venue
  — публичность контактов поставщикам регулируется showAdminContactsToSuppliers

Product
  — единый товар платформы
  — офферы разных поставщиков привязаны через SupplierProduct → Offer
  — barcode — сквозной ключ поиска: каталог / меню / склад / ревизия

ProductVariant
  — варианты управляются поставщиком в рамках своих товаров
  — master-level данные (без поставщика) правит только модератор/система

Offer
  — availabilityLevel, deliveryTerm, specialOfferText управляет только поставщик
  — цена фиксируется в SupplierOrderItem на момент заказа

ContractSupplier
  — поставщик не может самоназначить себя контрактным
  — приоритет и статус управляет только ADMIN заведения

Inventory
  — складская позиция может существовать без привязки к Product (productId nullable)
  — unit строго типизирован Enum KG / L / PCS / G / ML
  — minThreshold питает StockAlert (тип LOW_STOCK)

InventoryReservation
  — резерв не списывает фактический остаток, но учитывается в "доступном остатке"
  — isActive = false освобождает резерв без удаления записи

Menu
  — MenuItem.type = PRODUCT может ссылаться на Product
  — MenuItem.type = DISH использует TechCard (1:1)

StopList
  — стоп-лист относится к MenuItem, а не к Product
  — isActive = false снимает позицию без удаления записи

MenuItemTag
  — AUTO-теги (tagType = AUTO) нельзя редактировать вручную
  — isVenueShared = true — тег виден всем сотрудникам заведения
  — LINE_STAFF может создавать только личные теги (isVenueShared = false)

MenuItemAnalog
  — назначаются только ADMIN
  — ссылается на два MenuItems внутри одного заведения

MenuItemPairingStat
  — два FK на MenuItem: menuItemId и pairedMenuItemId
  — обновляется системой из SalesReportRow

TechCard
  — ингредиенты привязаны к InventoryItem, а не к Product

InventorySession
  — LINE_STAFF не видит expectedQty до сабмита (скрывается на уровне API)

Orders
  — Пользователь собирает одну общую корзину заведения
  — При оформлении заказа товары автоматически разбиваются по поставщикам
  — Каждому поставщику отправляется отдельная SupplierOrder
  — Поставщик может менять только статусы своей SupplierOrder (ACCEPTED / PROCESSING / SHIPPED)
  — Приёмка подтверждается заведением отдельно по каждой SupplierOrder
  — При подтверждении приёмки товары переходят на склад
  — При отклонении приёмки поставщику отправляется уведомление с причиной
  — SupplierOrderItem.total — денормализованное поле; бэкенд пересчитывает при любом изменении quantity или price

FileAsset
  — каждый файл обязан иметь владельца: uploadedByUserId или uploadedBySupplierId
  — CHECK (uploadedByUserId IS NOT NULL OR uploadedBySupplierId IS NOT NULL)
